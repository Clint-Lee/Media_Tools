## 二、抖音/小红书播放量的最终实测结论（重要，勿重走弯路）

1. **抖音播放量是平台服务端主动隐藏，不是采集手段问题。** 本轮实测：本服务匿名浏览器拿到 `play_count: 0` 占位；改用持有**服务器端 Cookie 池**的第三方解析服务 `api.douyin.wtf`（demo 会话登录，`douyin.content_detail` 端点），三个不同作品返回的 statistics 同样是 `play_count: null` 而 `digg_count` 正常。结论：任何匿名/第三方读取方都拿不到该字段；商业数据商（新抖/飞瓜/千瓜）对外提供的也只有"预估播放量"。
2. **小红书同理**：站内外都没有可核验的匿名播放来源（JSON-LD WatchAction 数值与点赞+收藏+评论合计一致，此前已拒绝）。
3. **快手详情 graphql 匿名直接返回 "Need captcha"**——按项目红线不处理验证码、不反复撞验证墙。

### 3.1 解决方案：互动推算预估播放（新模块 `lib/estimated-views.js`）

- 抖音按真实点赞 × 20（互动率基准 5%）、小红书 × 30（3.5%），保留两位有效数字（3889×20=77780 → 78000，预估不冒充精确）。
- 输出 `viewPrecision: 'estimated'`、`viewEvidence.status: 'estimated'`、`evidence.formula` 记录推算公式与 basedOn（点赞/评论/分享/收藏）。
- **绝不覆盖平台真实计数**（`playRaw != null` 时直接跳过）；点赞低于阈值（抖音<10、小红书<5）保持未知，不硬推。
- 全链路透传：`metric-evidence.normalizeMetric` 把 `estimated` 与 `source-rounded/unverified` 同列保护（不降级为 integer）；`data-quality` 新增 `estimatedViews` 单列统计；前端卡片显示"≈X 播放(预估)"并注明"互动推算预估（非平台数据）"。
- `HOTPOT_ESTIMATED_VIEWS=0` 一键关闭，恢复"未知不排名"的严格行为。
- 接入点：`live-sources.js` 抖音多来源与精选直连路径、`public-discovery.js` 小红书路径。抖音开放平台（DOUYIN_CLIENT_TOKEN，官方 hotsearch）路径有真实 play_count，预估自动不生效。

## 三、本轮修复的真实缺陷（按平台）

### 3.1 YouTube：点赞全为 0 的根因 + 修复

- **根因**：watch 页已从 `likeCountEntity` 改版为 `segmentedLikeDislikeButtonViewModel`（按钮组件）。旧提取链只剩约 1/6 命中率。
- **修复**（`lib/youtube-public.js parseWatch`）：三级降级——
  1. accessibilityText 精确数（"like this video along with 19,494,293 other people" → 19494293，integer）；
  2. 旧 `likeCountIfIndifferentNumber`（兼容未改版页面）；
  3. 按钮 `buttonViewModel.title`（"19M"，source-rounded，如实标近似）。
- **响应时序缺陷**：旧代码 `sortBy=views` 时 enrich 只 fire-and-forget，`apply()` 立即执行——点赞永远赶不上响应组装，且 2 分钟快照把无点赞版本存盘，用户永远看到 0。改为始终 `await notes.enrich(list)`（内部自带 8 秒上限，指标缓存 5 分钟内命中为 0 成本）。

### 3.2 YouTube：下载卡死的根因 + 修复

- **根因**：googlevideo 对裸流连接严重限流——实测音频流 5KB/s 龟速、视频流 197KB 后静默断流（axios 无 body 超时，任务挂 12 分钟）。
- **修复**（`lib/media-jobs.js`）：`platform=youtube` 的媒体任务改走 **yt-dlp 直接下载**（内建 Range/限流/签名对抗与音视频合并，实测 232MB/68s）；analyze/transcript 走 yt-dlp 音频轨 + ffmpeg 转码（wav 16k / mp3）。下载参数与 extractMetadata 一致（`--js-runtimes node:`、cookieFile、可选 MEDIA_PROXY）。
- **通用加固**：`downloadStream` 增加 45 秒停滞看门狗（googlevideo 中途停发但不关连接）+ 中断类错误自动整段重试（最多 3 次，不续传）。

### 3.3 YouTube：官方续页翻页接通

- innertube 响应里的续页结构是 `continuationItemRenderer.continuationEndpoint.continuationCommand.token`（不是 `.token` 直挂）。提取为 `nextCursor`，翻页请求体带 `continuation`。
- 契约：无上一页令牌时明确拒绝（"缺少上一页的官方续页令牌"）；响应无续页结构时 `hasMore=false`，不伪造页码。最多 10 页。
- 测试 `test/youtube-innertube.test.js` 已更新为新契约（旧断言"禁止伪分页"改为"官方令牌续页"），`npm test` 通过。

### 3.4 抖音翻页

- 旧代码 `page>1` 直接抛"抖音公开发现尚无可靠继续游标"。实际公开精选页（module/feed）支持按页深滚动（`collectDouyinPage` 的滚动次数本就是 page 的函数），热点榜只提供第1页（失败被多来源合并容忍）。放开后 P2 实测新增 39 条、全部有预估播放。

### 3.5 快手：CDN 域名轮换 + 上下文自愈

- **根因 1**：视频流下发域名轮换到 `djvod.ndcimgs.com`，旧白名单（kwaicdn/yximgs）误拒真实媒体 → "快手没有返回可验证的原站媒体地址"。
- **修复**（三处）：`kuaishou-public.js` 白名单加 `ndcimgs.com`/`gifshow.com` 并收集 manifest backupUrl 作备选；`safe-network.js` trustedCdnDomains 同步；`downloader-core.js` 防盗链头补 Referer。
- **根因 2**：长驻服务的共享匿名上下文积累风控状态后 graphql 停发，解析持续失败直到重启。
- **修复**：`withPage` 新增 `fresh` 选项（跳过共享上下文）；`extractPublicMetadata` 失败后换全新上下文重试（共 3 次尝试），等待 8→10 秒。
- **真实边界（如实保留）**：部分作品匿名不可看——页面会换成推荐流，`metadataFromDetail` 的身份核验正确拒绝顶替；详情 graphql 要求 captcha（不绕过）。可匿名观看的作品解析+下载完全可用。

### 3.6 小红书：http 流升级

- 官方流以 `http://sns-video-v3.xhscdn.com/...` 下发，`videoUrl()` 只收 https → 一律 NULL → "没有返回对应的视频地址"。
- 修复（`lib/red-public.js`）：对已核验的小红书媒体域名（xhscdn/xiaohongshu/xhsimg）允许 http 并升级为 https，不做任意重写。实测下载 1.8MB MP4 通过。

## 四、E2E 验证记录（可直接复用的脚本）

- `.cache/platform-sweep.js`：7 平台榜单覆盖扫描（条数/播放/点赞/证据状态分布）。
  `node .cache/platform-sweep.js` 或指定 `node .cache/platform-sweep.js douyin,youtube`
- `.cache/e2e-yt-download.js <url> <kind> <minutes>`：解析 → 任务 → 阶段进度轮询 → 文件魔数校验。
  **注意必须传 mediaId**（脚本已内置：真实 UI 流程会复用 /api/parse 的解析结果；不传会触发二次解析，快手等时序敏感平台可能失败）。
- 媒体环境：`npm run setup:media`（本轮全新安装 exit 0；ASR ready 输出验证）。
- 服务启动：`HOTPOT_PREWARM=0 node server.js`（跳过预取更快）；当前网络 YouTube/TikTok/X 直连可用，本机 Clash(7897) 自动探测仅影响 axios 层。
