# VidFetch 多平台解析修复说明（接手文档）

> 本文记录本次修复的**根因、方案、实测证据与后续维护方式**。
> 核心目标：让抖音、快手、小红书等平台能真正拿到视频与统计（播放量/点赞/评论…）数据，且**所有数字必须真实，不许填假值**。

---

## 一、问题现象

- B站：能解析出视频，但**播放量等统计数据从未展示**
- 抖音：视频解析不出，播放量为 0
- 快手 / 小红书：同样拿不到视频与互动数据

---

## 二、根因（全部经过实测验证，非推断）

### 1. 抖音解析失败：拦截器在等一个永远不会发生的请求

| 代码位置 | 问题 |
|---|---|
| `aweme/v1/play` + `video_id=` 正则 | 抖音 Web 端播放走 `douyinvod.com/.../video/tos/...`，URL 里**根本没有 `video_id=`**；实测 puppeteer 打开视频页 **media 请求数 = 0** |
| `/aweme/detail/`、`/aweme/post/`、`/aweme/iteminfo/` 响应嗅探 | 抖音 Web 端实际路径是 `/aweme/v1/web/aweme/detail/`（多一个 `web`），且**页面不会自己发起**，必须主动调用；实测捕获到的 aweme 响应只有 `hot/search/list`、`social/count` |
| `iesdouyin.com/share/video/{id}/` 的 `_ROUTER_DATA` | 仍返回 200，但 `loaderData` 里 `videoInfoRes: null`、`item_list: []`；换 Baiduspider / Googlebot / Bytespider / PC UA 全部一样 |
| `/aweme/v1/web/aweme/detail/` 直连 | `403 Blocked by ArgusSecurityPlugin Uifid Not Found` |

**关键结论**：Argus 校验的是**请求签名（a_bogus/X-Bogus）**，不是 cookie。
实测：把 puppeteer 导出的全套 cookie（ttwid/UIFID/s_v_web_id/msToken）用 node axios 直连 → 仍 403；
但在 `page.evaluate` 里发 fetch → **200，aweme_detail 完整**。

→ 正确做法：**让浏览器页面替我们签名**，node 侧永远不要手写签名算法。

### 2. 抖音下载失败：Referer 被人为删掉了

`server.js` 下载分支原注释写着"不要提供 Referer"，而实测：

| 请求头 | 结果 |
|---|---|
| 不带 Referer | `403 text/html` |
| 带 `Referer: https://www.douyin.com/` | `200 video/mp4` |

### 3. 播放量"全是空"：两类完全不同的原因

**原因 A：B站的数据一直都在，只是代码没读**
`api.bilibili.com/x/web-interface/view` 返回的 `data.stat` 包含 `view`/`danmaku`/`like`/`reply`/`favorite`/`coin`/`share`，全部真实可用。旧代码只取了 `title`/`pic`/`desc`/`cid`/`aid`/`bvid`，**从未读取 `data.stat`**。

**原因 B：抖音普通视频的真实播放量，Web 端确实拿不到**

穷举过的所有路径（全部失败）：

- `statistics.play_count` → 恒为 `0`
- `/aweme/v1/web/aweme/statistics/`、`/aweme/v2/web/aweme/detail/` → `404`
- `/aweme/v1/web/multi/aweme/detail/` → 返回 `null`
- 移动端 `aweme.snssdk.com`、`api5-normal-c-lq.amemv.com`、`api22-normal-c-useast2a.tiktokv.com` 的 detail → 空响应
- `iesdouyin.com/share/video/{id}/` → `_ROUTER_DATA` 无数据
- 搜索接口 → 未登录返回"请先登录"

关于 `hot_list.view_count`：它**只有热榜视频才有值**（实测 8 个视频中仅 2 个热榜视频有，其余为 `undefined`）。
且该字段的**统计对象、时间范围、是否累计播放均未得到验证**，因此本实现**不把它当作真实播放量**，而是作为独立字段 `hotListViews` 单独标注（见下文"设计取舍"）。

### 4. 快手：字段藏在另一个 GraphQL 查询里

- `photo.viewCount` = **真实播放量**（常为 `"29.6万"` 这类中文字符串，需解析）
- `VisionVideoDetailPhoto` 类型**没有** `commentCount` / `shareCount` 字段（GraphQL 直接报 `Cannot query field`）
- 评论数在 `commentListQuery` 里，字段是 **`commentCountV2`**（实测 402 / 613 / 2318），而 `commentCount` 是 `null`
- GraphQL introspection 被禁用；自行拼 query 调 `visionVideoDetail` 会触发 `Need captcha`

### 5. 小红书：必须带 `xsec_token`

- 缺 `xsec_token` → 跳 404（`error_code=300031`）
- 互动数据在 `window.__INITIAL_STATE__.note.noteDetailMap[id].note.interactInfo`：
  `likedCount`/`commentCount`/`collectedCount`/`shareCount`，**均为中文字符串**（如 `"4.2万"`）
- 小红书**不公开播放量**
- 视频直链：状态树是 MobX 深层嵌套不可靠，`video.src` 是 `blob:`；
  改用 `page.on('response')` 嗅探 `content-type: video/mp4`（`sns-video-v*.xhscdn.com/stream/...`）

## 三、解决方案

### 架构：三条通道

```
通道 A「直连 API 快车道」node 侧 axios 直接拿
   └─ B站 : /x/web-interface/view + data.stat

通道 B「页面上下文签名」在真实浏览器页面里 fetch，让站点 JS 补签名
   └─ 抖音 : www.douyin.com 同源 → /aweme/v1/web/aweme/detail/

通道 C「页面状态树 / 响应嗅探」
   ├─ 快手   : GraphQL visionVideoDetail 响应 + commentListQuery 补评论数
   └─ 小红书 : __INITIAL_STATE__ + content-type:video/mp4 媒体嗅探
```

### 统一统计数据结构（绝不造假）

```js
stats: {
  metrics: {                       // 结构化，带来源
    play:    { value: 107439276, source: 'stat.view' },
    danmaku: { value: 151011,     source: 'stat.danmaku' },
    like:    { value: 2957995,    source: 'stat.like' },
    comment: { value: 238060,     source: 'stat.reply' },
    collect: { value: 1555977,    source: 'stat.favorite' },
    coin:    { value: 1285073,    source: 'stat.coin' },
    share:   { value: 500405,     source: 'stat.share' },
    recommend: null
  },
  missing: ['recommend'],          // 平台明确不提供的指标
  note: '',                        // 给用户看的诚实说明
  // 便捷字段（兼容旧前端，直接是数字或 null）
  play: 107439276, like: 2957995, ...
}
```

设计原则：
- 每个指标要么是真实数字，要么是 `null`
- 带 `source` 标明来源，便于排查与标注
- `missing` 明确告诉前端"平台不提供哪些指标"
- **绝不填假数据、绝不做"点赞×N"的估算去冒充播放量**

### 各平台字段映射

| 平台 | 播放 | 点赞 | 评论 | 收藏 | 分享 | 其它 |
|---|---|---|---|---|---|---|
| B站 | `stat.view` | `stat.like` | `stat.reply` | `stat.favorite` | `stat.share` | `stat.danmaku` 弹幕、`stat.coin` 投币 |
| 抖音 | ❌ 不提供 | `digg_count` | `comment_count` | `collect_count` | `share_count` | `recommend_count` 推荐 |
| 快手 | `photo.viewCount` | `realLikeCount` | `commentCountV2` | ❌ | ❌ | — |
| 小红书 | ❌ 不提供 | `likedCount` | `commentCount` | `collectedCount` | `shareCount` | — |

### 设计取舍：为什么 `hot_list.view_count` 不填进 `play`

Astra 复核时指出：接口返回了数值，**不等于**已确认其统计对象、时间范围与累计播放口径。
因此本实现把它放进独立字段：

```js
stats.hotListViews = { value: 1505355, source: 'hot_list.view_count', verified: false }
```

前端单独展示并标注"统计口径未核验，不等同于播放量"。
宁可少显示一个数字，也不展示一个可能误导用户的数字。

## 四、实测结果

金丝雀探针 `node probe_platforms.js` —— **5 项全部通过**：

| 用例 | 耗时 | 结果 |
|---|---|---|
| B站 | 288ms | 播放 1.07亿、弹幕 15.1万、点赞 295.8万、投币 128.5万 |
| 抖音-热榜 | 4296ms | `hotListViews` 150.5万（标注未核验）+ 点赞/评论/收藏/分享 |
| 抖音-普通 | 3520ms | `play: null` + 说明"接口未提供可核验播放量"，互动数据真实 |
| 抖音-分享文本 | 3530ms | 能从含中文 emoji 的分享文案提取链接 |
| 快手 | 3768ms | 播放 18.3万、点赞 1.9万、评论 240（来自 `commentCountV2`） |

下载链路：抖音直链 `200 video/mp4`，实测下载 1.5MB 成功。

## 六、后续维护

### 1. 金丝雀探针（接口变更当天发现）

```bash
node probe_platforms.js --base http://127.0.0.1:3000 --token <TOKEN>
```

退出码 `0` = 全部通过；`1` = 有平台失效。可挂 cron / 任务计划程序告警。

探针包含一条**反向断言**：抖音普通视频的 `stats.play` **必须为 `null`**。
这是为了防止以后有人"好心"填个估算值冒充播放量。

### 2. 抗变更原则

- 解耦"取 id"与"取 detail"，一方变了不牵连另一方
- **签名永远外包给站点 JS**（`page.evaluate`），算法变了也不用改
- 存 `aweme_id` 而非 CDN 直链（直链带 `x-expires`，会过期）
- **不要篡改 CDN URL 的 query 参数**（`x-expires`/`x-signature` 相互绑定，改了会 403）
- 快手不要自行拼 GraphQL query，会触发 `Need captcha`；用页面自身环境发请求

### 3. 已知限制

- 抖音：普通视频无播放量（平台限制，非代码缺陷）
- 抖音：已登录/私密作品会返回 `filter_reason: status_self_see`，属正常业务状态
- 快手：无收藏/分享数（GraphQL 类型里就没有这两个字段）
- 小红书：无播放量；图文笔记（`type: normal`）无视频流，但互动数据仍会返回
- 小红书：链接必须带 `xsec_token`
