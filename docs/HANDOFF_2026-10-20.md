## 三、核心结论：抖音 Web 端播放量是平台级隐藏计数

### 3.1 已实测排除的 10 条路线（全部失败，证据在 .cache/）

| # | 路线 | 实测结果 |
|---|---|---|
| 1 | `/aweme/v1/web/aweme/detail/` 匿名 | `play_count: 0`，`digg_count: 1000` 正常 |
| 2 | 同上 + 注入 `sessionid` | 仍为 0 |
| 3 | 同上 + 完整登录 Cookie 集 | 仍为 0 |
| 4 | 移动端 UA（iPhone Safari） | 页面根本不发 aweme XHR |
| 5 | `iesdouyin.com/share/video/{id}/` | HTML 无 statistics |
| 6 | `/aweme/v1/web/aweme/post/` | 403 ArgusSecurityPlugin Uifid Not Found |
| 7 | `/aweme/v1/web/search/item/` | status_code 2483 请先登录 |
| 8 | 移动端 API（aweme.snssdk.com / amemv） | 空响应（缺签名） |
| 9 | 第三方公开 API（douyin.wtf/urlebird/tikcdn/60s 其他端点） | 404 / CF 403 / TLS 重置 |
| 10 | 旧 `CreativeCenterGetTopContentsList`（TikTok） | 400，接口已改版 |

**关键判断**：`play_count: 0` 与 `digg_count: 1000` 同时出现时，0 不是
"零播放"，而是**平台不向当前访问者返回播放计数**的占位。
对应 Astra 报告的 `view_status: ambiguous_zero` → `public_view_count: null`。

### 3.2 Astra 确认的社区现状（2026-10-20）

- `Evil0ctal/Douyin_TikTok_Download_API` 维护者 2025-03-11 确认
  **Web 播放量接口已下架**（Issue #578），社区转用付费接口。
- 唯一低门槛付费候选：TikHub App V3 统计接口
  （`GET https://api.tikhub.io/api/v1/douyin/app/v3/fetch_video_statistics?aweme_ids=...`，
  每次最多 2 个 aweme_id，需第三方账号；返回值未经本项目后台对账）。
- 签名参数（`a_bogus`=SM3+RC4+自定义Base64、`X-Bogus`=MD5+RC4、
  `msToken`=风控token、`ttwid`=访客标识）只解决**请求校验**，
  **不能"解密"服务端返回的 0**。
- 社区经验点赞率 1%-3%（估播放 = 赞×33~100）**未被本项目采用**——
  非抽样验证结论，只报告赞/评/享/藏四项原始值。

### 3.3 抖音的处理方式（诚实口径）

- `play_count: 0` → `viewEvidence.status = 'placeholder-zero'`，`playRaw = null`
- 不参与播放量排名，改用已公开的赞/评/享/藏排序
- 新增 `interactRaw` 字段（互动总量），字段名明确表达它不是播放量
- UI 显示"共 N 件未公开播放量"
- **登录态补全钩子**（`lib/douyin-views.js`）：本机保存了抖音登录态
  （`npm run platform:login -- douyin`）才尝试逐条请求详情改写播放量；
  未配置时行为与之前完全一致，不会改变匿名用户的结果。

## 四、本轮新增的数据源（全部实测通过）

### 4.1 抖音官网热点视频榜（lib/douyin-hotspot.js）

浏览器访问 `douyin.com/hot` 时页面会请求的官方接口：

```
GET /aweme/v1/web/channel/hotspot
    ?device_platform=webapp&aid=6383&channel=channel_pc_web
    &tag_id=&count=10&Seo-Flag=0&channel_id=99&version_code=170400
```

返回 `status_code: 0` + `aweme_list`（10条/次，`has_more: 1`），含完整
`aweme_id/desc/author/cover/create_time/duration` 和真实互动计数。

### 4.2 TikTok 详情页真实播放量（lib/tiktok-views.js）

```
GET tiktok.com/@i/video/{id}
  → #__UNIVERSAL_DATA_FOR_REHYDRATION__
      .__DEFAULT_SCOPE__["webapp.video-detail"].itemInfo.itemStruct.stats.playCount
  → （旧结构）#SIGI_STATE.ItemModule[{id}].stats.playCount
```

实测 5/5 拿到真实值（127.7M / 50.4M / 46.6M / 29.5M / 46.6M）。
核验规则：`itemStruct.id` 必须与请求 id 一致，否则丢弃（不用推荐视频顶替）。

### 4.3 TikTok Creative Center 话题趋势榜（lib/tiktok-creative.js，Astra 挖出）

```http
POST https://ads.tiktok.com/CreativeOne/KnowledgeAPI/GetHashtagList
Content-Type: application/json
Referer: https://ads.tiktok.com/creative/creativeCenter/trends/hashtag

{"timeRange": 7, "countryCode": "US", "page": 1, "limit": 20}
```

返回 `hashtagName / rankIndex / publishCnt（作品数）/ popularityCurve（0-100热度曲线）/ topCreators`。
**口径隔离**：热度指数与作品数都不是播放量，走独立 `topicRanking` 字段透出，
不与视频混榜（测试有断言守着这条边界）。同族 `GetSongList` / `GetCreatorList`
常量已留，未启用。

### 4.4 YouTube 免 Key 检索（lib/youtube-innertube.js）

```
POST https://www.youtube.com/youtubei/v1/search?prettyPrint=false
{"context":{"client":{"clientName":"WEB","clientVersion":"2.20240101.00.00","hl":"zh-CN","gl":"US"}},
 "query":"music","params":"CAMSAhAB"}   // protobuf: sortBy=viewCount + type=video
→ contents[].videoRenderer[].viewCountText ("209,277,527 views")
```

- 页面上下文 `fetch`，复用真实会话，不维护签名
- 上传时间过滤：`today/3days/7days/1month/6months` 各有对应 params
- `1.2M`/`3.4万` 记为 `source-rounded`；相对时间只用于时效筛选
- 失败自动退回原有 `results` 页 HTML 解析路径

### 4.5 公开热榜聚合兜底（lib/platform-hotlists.js）

抖音官方热搜接口受限时，退回 60s API（开源 github.com/vikiboss/60s）的
真实话题与平台热度值；热度明确标注"不是视频播放量"。

## 六、踩坑记录（给下一个接手的人）

1. **Node.js 顶层 await**：测试文件里直接写顶层 `await` 会被当成 ESM 报
   `require is not defined in ES module scope`，必须包进 `(async()=>{})()`。
2. **PowerShell 中文输出**：`git diff` / node 输出里的中文在 PowerShell 里显示
   为 `?`，文件本身是 UTF-8 正确的；要精确匹配中文行时用 Node 脚本读文件
   处理，别在 PowerShell 里字符串比对。
3. **puppeteer 找不到 Chrome**：本机 `C:\Users\32949\.cache\puppeteer` 没有下载版
   Chrome，但系统装了 Chrome。已在 `lib/live-sources.js` 和
   `scripts/platform-login.js` 加入可执行路径探测
   （PUPPETEER_EXECUTABLE_PATH > Program Files > LOCALAPPDATA）。
4. **live-sources 的 memo 缓存**：改了采集逻辑后测试看不到新字段，多半是
   外层 `memo` 缓存了旧结果（内存 + `.cache/source-snapshots-v3/` 磁盘双缓存，
   5 分钟 TTL）。直接调 `publicPageVideos` 传 `memo: async(k,w)=>w()` 验证。
5. **boundedMap 返回结构**：`results[index] = { value: worker的结果 }`，
   worker 返回 `{name, value}` 时实际是 `{value: {name, value}}`，要 `.map(r=>r.value)`。
6. **innertubeVideo 的 walk 陷阱**：`walk(data, node=>node.videoRenderer)` 收集的
   是**包装对象**，取字段要 `node.videoRenderer.videoId`，不是 `node.videoId`。
7. **测试数据 ID 长度**：抖音 aweme_id 必须匹配 `/^\d{15,22}$/`，测试用 `'1'`
   这种短 ID 会被 `hotspotVideo` 静默丢弃，导致"明明 mock 了数据却 list=0"。

## 七、合规边界（本轮遵守的规则）

1. **不破解签名**：a_bogus / X-Bogus / msToken / x-s / x-t 均未实现——
   签名解决请求合法性，不解决平台不公开播放量。
2. **不绕验证码**：滑块/登录墙直接如实报错，不接打码平台，不用固定素材替代。
3. **不改写计数**：0、缺失、缩写展示值分别记为 placeholder-zero /
   not-provided / source-rounded，绝不互相转换。
4. **登录态由用户自主保存**：`npm run platform:login -- douyin` 由用户本人在
   官网完成，Cookie 只存本机 `.runtime/platform-sessions/`，不输出不上传。
5. **频率克制**：TikTok 详情补全每轮最多 8 条、60s 冷却、5 分钟 TTL；
   各榜单均有 memo 缓存，不做高频轮询。
