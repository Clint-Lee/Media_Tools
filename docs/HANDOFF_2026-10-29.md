## 2. 真正修复了什么

1. **真实播放榜门禁**：默认关闭互动预估；`public/ranking.js` 拒绝 estimated 精度/证据/来源。旧快照、索引和显式实验配置都不能把估算洗成真实排名。覆盖率及联网严格验收也使用同一判据。
2. **指标独立合并**：采集索引分别比较元数据、播放和点赞的观测时间；较新点赞不再把旧播放一起覆盖。较旧元数据附带的新计数仍能写入，明确 null 能撤销旧值，重启后保持。
3. **统一解析保留参数**：新增 `lib/media-metrics.js`，B站详情、抖音原站/匿名页面、小红书互动、快手详情、TikTok embed 及 yt-dlp 实际返回的计数不再在 `downloader-core` 丢失。每种指标独立归一化、保留来源/精度；未知不是零。
4. **X 指标语义**：核对 yt-dlp 源码发现 TwitterIE 的 `view_count` 来自帖子 `views.count`，不能当视频播放。本项目将此值单独标为 `postImpressionRaw`；原站匿名视频配置和媒体实体的视频计数才可进入播放量。解析 X 链接也尝试现有官方视频统计补全。
5. **TikTok 后台补数**：适配 statsV2 字符串整数；普通 HTTP 请求即便命中原发现快照，也会回填已完成的详情并写入采集索引。新明确隐藏状态不能被旧详情复活。不增加自动整屏刷新。
6. **媒体运行时**：yt-dlp 升至官方 `2026.10.26`；不再强制使用不兼容的 Node20。支持 `YTDLP_JS_RUNTIME`，Windows 安装独立 Node24 并核对官方 SHA256；系统 Node 不变。元数据可单独使用 `metadataOnly`，不要求下载格式可用；`anonymous` 模式不读取个人 Cookie。这两个可选参数已有测试，不等于已把新采集队列接入所有榜单。
7. **下载合并**：yt-dlp 下载明确收到项目自带的 FFmpeg 路径（本机没有全局 ffmpeg），增加10MiB分块及单文件2GiB声明上限。后者不是整任务总预算，未知长度/输出文件仍需资源治理。
8. **小红书原画回退**：参考 yt-dlp 的 `originVideoKey` 思路，在缺少格式流时使用本作品返回的相对 key 和固定官方 CDN；拒绝路径穿越/外域，解析仍探测实际媒体响应。

## 4. 指定开源项目，读到的实际能力

### yt-dlp

实际浅克隆至 `.cache/research/yt-dlp`，核对提交 `f264a6c`（2026.10.26官方发布）。当前 Python3.12满足新版最低3.11要求；[官方版本说明](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.10.26)、[运行时实现](https://github.com/yt-dlp/yt-dlp/blob/f264a6c/yt_dlp/utils/_jsruntime.py)。

- [Douyin提取器](https://github.com/yt-dlp/yt-dlp/blob/f264a6c/yt_dlp/extractor/tiktok.py)仍读取web detail，并非额外的播放量数据库。本轮不带 Cookie 对同一作品实际返回403及需要新技术 Cookie的提示；现有浏览器原站路径能拿到媒体/点赞，但播放仍零占位。
- [小红书提取器](https://github.com/yt-dlp/yt-dlp/blob/f264a6c/yt_dlp/extractor/xiaohongshu.py)提供视频流与原画key回退；不能因其支持下载而推导它提供独立播放统计。
- [Twitter提取器](https://github.com/yt-dlp/yt-dlp/blob/f264a6c/yt_dlp/extractor/twitter.py)的帖子曝光映射已在本项目隔离；这是适配器需要处理的字段语义，而不是依赖通用名字猜测。

### Galaxy 网站和桌面端

- 指定网站仓库的 [config.ts](https://github.com/bhwa233/galaxy-downloader/blob/main/src/lib/config.ts) 将解析指向独立后端；[统一响应类型](https://github.com/bhwa233/galaxy-downloader/blob/main/src/lib/types.ts)主要是媒体信息和下载地址。对本轮同一抖音作品调用一次公开 `/api/parse`，HTTP200且有媒体地址，但返回中没有播放/点赞字段。没有将这个公共服务接为默认后端，也没有做批量压测。
- 进一步浅克隆关联 [Galaxy桌面端](https://github.com/bhwa233/galaxy-downloader-client)，实际版本提交 `a1f5d97`，不是仅看网页宣传。其 [engine/main.py](https://github.com/bhwa233/galaxy-downloader-client/blob/a1f5d97/engine/main.py)依赖 yt-dlp/FFmpeg，实际带10MiB下载分块；[抖音列表实现](https://github.com/bhwa233/galaxy-downloader-client/blob/a1f5d97/electron/services/listings/douyin.ts)也避开web列表的零占位play_count。短剧全集的play_vv是合集统计，不能拿来当某条视频的播放。
- 桌面端支持个人浏览器登录态、部分平台/分页会要求登录；这不是默认匿名服务可直接照搬的方案。网站和桌面端许可证不同，参见各自LICENSE；本轮只借鉴公开协议/参数思路，没有复制其实现或绕过授权。

另外复核了 [f2](https://github.com/Johnserf-Seed/f2)、[TikTokDownloader](https://github.com/JoeanAmier/TikTokDownloader)、[MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)、[Evil0ctal下载API](https://github.com/Evil0ctal/Douyin_TikTok_Download_API)的公开资料，不能用支持平台名单证明所有指标匿名可得；后续需逐端点、同作品核验。没有安装它们、创建身份池或接入未经验证的付费服务。

## 5. 下轮按这个顺序接

1. **补源必须附响应证据**：对抖音/小红书寻找同作品的独立视频播放字段，记录端点、作品ID、指标定义、精度、采集时刻、匿名/应用授权条件。先用一个样本跑通，再做有界队列，不把隐藏零/点赞总和/合集总数混用。现有 `douyin-open` 的应用级授权不要求终端登录，但需运营者权限，不能在没有凭证时宣称接通。
2. **发现/排序与媒体解析分离**：本轮补齐的是解析返回参数，不是自动把每次粘贴的私人观看记录写进公共排行榜。若新增参数补全队列，要批量去重、按字段合并、限时、保留原采集时刻；不能每张卡串行跑一次Python。
3. **冷查延迟**：YouTube API仍约11秒；公开点赞当前等待详情队列，发现源还会等待多个浏览器来源。30条懒加载主要减少DOM，不能减少既有后端全量采集。可在不换排名/不整屏闪烁前提下，拆出指标更新接口或按主动选择指标决定阻塞预算，并用真实计时验收。
4. **下载与分析**：本轮七个平台各一个样本完整MP4通过，但不等于任意作品、任意网络、任意时刻稳定。继续补删除/私密/静音/过期直链/无字幕等失败路径；TextRank只做抽取兜底，神经语义模型或远程LLM需单独配置与质量验收。
5. **生产限制不变**：单进程JSON索引；可信反代/IP、安全Cookie、速率/并发/整任务磁盘带宽预算、Python与Chromium出站隔离、Linux冷机安装仍需专项处理。参考[部署清单](DEPLOYMENT.md)，注意它的旧行号和历史状态不能盖过本轮代码。
